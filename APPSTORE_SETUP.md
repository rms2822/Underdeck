# Publishing Underdeck to the App Store — from an iPhone, no Mac needed

This covers the one hard truth first: **an actual App Store build has to
pass through Xcode on macOS at some point.** That's Apple's own
requirement for code-signing and submission — nothing to do with Unity,
and nothing I can route around. What *can* be routed around is **you**
needing to own or operate that Mac. The setup below has GitHub's cloud
build servers do the Xcode part, triggered by a button tap from your
phone. You never see Xcode; you never need Terminal.

Everything technical is already built and sitting in this repo:
- The game is wrapped as a real native iOS app project (`ios/`) using
  Capacitor — the same widely-used tool many real App Store apps use to
  ship an HTML/JS/CSS game as a native app. It's a genuine Xcode project,
  generated by Capacitor's own tooling, not hand-written.
- `.github/workflows/ios-release.yml` — a pipeline that builds, signs, and
  uploads to TestFlight/App Store Connect automatically on a macOS runner
  in GitHub's cloud, whenever you tap "Run workflow."
- `fastlane/` — the build/signing/upload automation the pipeline runs.

**What's below is the part only you can do** — it involves your own Apple
ID, a payment, and identity verification, so I can't do it for you. It's a
one-time setup (~30–45 minutes spread over however long Apple's review
steps take), then every future release is just "tap Run workflow."

I have to be upfront about one thing: **I could not test-run any of this**
— there's no macOS/Xcode/Apple Developer account available in the
environment I built it in. Everything here follows well-documented,
widely-used patterns (this exact Capacitor + Fastlane + GitHub Actions
combination is extremely common), but expect the first run to possibly
need one or two small fixes — normal for any first-time mobile CI/CD
setup, not a sign something is fundamentally wrong. If it fails, send me
the error from the Actions log and I'll fix it.

## 1. Create an Apple Developer account ($99/year)

1. In Safari, go to **developer.apple.com/programs/enroll**.
2. Sign in with (or create) an Apple ID, and enroll — this requires a
   one-time $99 payment and Apple's identity verification, which can take
   anywhere from minutes to a day or two.
3. Once approved, you have access to **App Store Connect**
   (appstoreconnect.apple.com) and the **Apple Developer** portal
   (developer.apple.com/account) — both work fine in mobile Safari.

## 2. Find your Team ID

1. Go to **developer.apple.com/account** → **Membership details**.
2. Copy the **Team ID** (a 10-character code like `A1B2C3D4E5`). You'll
   need this in step 6.

## 3. Register the app's Bundle ID

1. Go to **developer.apple.com/account/resources/identifiers/list**.
2. Tap **+** → **App IDs** → **App**.
3. Description: `Underdeck`. Bundle ID: **Explicit** —
   enter exactly `com.underdeckgame.app`
   *(this must match `capacitor.config.json`'s `appId` in this repo
   exactly — if you want a different bundle ID, tell me and I'll update
   the repo to match before you register it)*.
4. Leave capabilities at their defaults. **Register**.

## 4. Create the App Store Connect app record

1. Go to **appstoreconnect.apple.com** → **My Apps** → **+** → **New App**.
2. Platform: iOS. Name: `Underdeck` (or whatever you'd like the store
   listing to say — the internal bundle ID doesn't have to match the
   display name).
3. Primary language: English (or your choice).
4. Bundle ID: select the `com.underdeckgame.app` one you just registered.
5. SKU: any unique string, e.g. `underdeck001`.
6. **Create.**

*(You don't need to fill in screenshots/description/pricing yet — that's
Part 2, after you have a build. This step just reserves the app record so
uploads have somewhere to land.)*

## 5. Generate an App Store Connect API key

This is what lets the GitHub-hosted Mac authenticate as you, without ever
typing your Apple ID password into a CI system.

1. In App Store Connect: **Users and Access** → **Integrations** tab →
   **App Store Connect API** → **Generate API Key** (or the **+** button).
2. Name: anything, e.g. `github-ci`. Access: **App Manager**.
3. **Generate.** You'll see a row with:
   - **Key ID** (short code)
   - **Issuer ID** (a UUID, shown above the key list)
   - A **Download API Key** link — **tap it now**, you can only download
     the actual key file *once*. It downloads a file named
     `AuthKey_XXXXXXXXXX.p8`.
4. Tap the downloaded file in Safari's downloads (or open it via the
   **Files** app) to preview it — it's a small plain-text file starting
   with `-----BEGIN PRIVATE KEY-----`. You'll copy its full contents in
   the next step, so keep this open or note where it's saved.

**Treat this file like a password** — anyone with it can act as your
Developer account's API integration. Don't post it publicly.

## 6. Add the secrets to your GitHub repo

1. On **github.com**, go to `rms2822/Scroundel` → **Settings** → **Secrets
   and variables** → **Actions** → **New repository secret**.
2. Add each of these four (exact names matter — the workflow reads them
   by these names):

   | Secret name | Value |
   |---|---|
   | `ASC_KEY_ID` | the Key ID from step 5 |
   | `ASC_ISSUER_ID` | the Issuer ID from step 5 |
   | `ASC_KEY_CONTENT` | the **entire contents** of the `.p8` file from step 5, pasted as-is (including the `-----BEGIN PRIVATE KEY-----` / `-----END PRIVATE KEY-----` lines) |
   | `APPLE_TEAM_ID` | the Team ID from step 2 |

   No encoding or terminal needed — GitHub's secret box accepts multi-line
   paste directly.

## 7. Run the build

1. On github.com: `rms2822/Scroundel` → **Actions** tab → **iOS Release
   (build + upload to TestFlight)** (left sidebar) → **Run workflow**
   button → pick the branch (`claude/scoundrel-game-n427my`, or wherever
   this ends up) → **Run workflow**.
2. It takes roughly 10–20 minutes. Tap into the running job to watch logs
   live, same as any GitHub Actions run.
3. On success, a new build appears in App Store Connect under your app →
   **TestFlight** tab within a few more minutes (Apple's own processing
   time after upload).

If it fails, open the failed step's log, copy the error text, and send it
to me — I'll fix the workflow/Fastfile and you re-run.

## Part 2 — from a successful TestFlight build to a public App Store listing

Once a build shows up in App Store Connect:

1. **Test it first via TestFlight** (recommended): App Store Connect →
   your app → **TestFlight** tab → add yourself as an internal tester →
   install the **TestFlight** app from the App Store on your iPhone → the
   build appears there to install and actually play, exactly like a real
   app, before anyone else ever sees it.
2. When ready to submit: App Store Connect → your app → **App Store**
   tab → fill in the listing (screenshots, description, category, privacy
   answers, age rating, pricing) → attach the build from step 7 above →
   **Submit for Review**.
3. Apple's review typically takes 24–48 hours. They'll email you the
   outcome; rejections come with a specific reason and are usually a
   quick fix (or occasionally a question you answer in the Resolution
   Center, all doable from Safari).

All of this — TestFlight, the listing form, submission, and review status
— is normal App Store Connect website usage and works, if a little
cramped, in mobile Safari.

## If you ever want to change the bundle ID / app name

- Bundle ID lives in `capacitor.config.json` (`appId`) and must always
  match what's registered in the Apple Developer portal and used in
  `fastlane/Appfile`'s default.
- Display name lives in `capacitor.config.json` (`appName`) and
  `ios/App/App/Info.plist`'s `CFBundleDisplayName`.

Tell me if you want either changed and I'll update the repo to match
before you register anything with Apple.
